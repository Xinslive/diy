# 后端**运行时**依赖（生产服务真正 import 的东西）。
#
# **为什么要拆。** 原来这里是 11 行全 `>=`，其中还混着 pytest ——
# 于是「装运行环境」和「装测试工具」变成同一件事，生产机器上躺着 pytest，
# 而发布脚本 `deploy/deploy.sh` 每次 `pip install -r requirements.txt` 装到的
# 版本又跟测试时跑的那套没有任何关系。测试全绿和生产能跑之间，缺一条版本等价的
# 保证。拆开之后：
#
#   requirements.txt      运行时依赖，只有人工抬下界才会变
#   requirements.lock      运行时**逐包定版**，发布/镜像/CI 都装它
#   requirements-dev.txt   开发依赖（在运行时之上叠加）
#   requirements-dev.lock  开发环境逐包定版，本地和 CI 用它
#
# **下界不是随手写的。** 这里的下界取的是 `backend/.venv` 里实测跑通全部测试的
# 那个版本，不是「随便一个看起来合理的数」。理由有两层：
#   1. 版本等价：下界低于实测版本，`>=` 就等于放行任意更新的版本，CI 和生产
#      还是会漂 —— 那正是 lockfile 要解决的事；
#   2. 少数几项另有硬约束，见各条注释。
#
# 想升级：改这里 → 重新生成 lock（见 lock 文件头）→ 跑全量测试 → 提交。
# 不要只改 lock，否则下次谁按 .txt 重新生成，升级就被静默回滚了。

# 下面这个不是「凑个下界」：models/ 全部用 SQLAlchemy 2.0 的声明式写法
# （Mapped[] / mapped_column）。1.4 下这套写法不成立。
SQLAlchemy>=2.1.4

# 项目用 psycopg3 的驱动名（postgresql+psycopg://）。psycopg2 不认这个 URL，
# 装成 psycopg2 会得到一个「连不上库」的错误，而不是一个明显的缺依赖错误。
psycopg[binary]>=3.3.6

# 生产 systemd 单元走 uvicorn（见 deploy/systemd/cwq-api.service），
# Docker 镜像里的 gunicorn worker 也基于 uvicorn.workers。
uvicorn[standard]>=0.54.0

FastAPI>=0.143.0
alembic>=1.20.0
pydantic-settings>=2.15.0

# app/core/security.py 的 jwt.decode 走 algorithms= 白名单校验，PyJWT 2.x 才对
# 这条路径给出确定的校验行为。
PyJWT>=2.15.1

# 导入/导出凭证与模板都要读 xlsx。
openpyxl>=3.1.5

# openpyxl 的**可选**加速项：装了就走 libxml2，没装就走纯 Python 的
# ElementTree，两条路都能跑，差别只在快慢 —— 所以它不装也能启动，不会变成
# 新的缺依赖故障。
#
# 为什么要装：Excel 导入是这套系统的核心路径（上限允许 20MB / 5000 张凭证），
# 而 xlsx 本身就是一堆大 XML。实测（openpyxl 3.1.5，5000 行 × 12 列，
# 同一台机器各跑两遍取稳定值）：写 0.36s -> 0.24s，读持平，
# 合计 0.62s -> 0.50s。收益集中在**写**这一侧（报表导出）。
#
# 代价要说清楚：
#   * 它是二进制 wheel（libxml2/liblzma 静态链进去），给 Linux/Windows/macOS
#     都发预编译包；但在没有 wheel 的平台会退回源码编译，那需要系统装
#     libxml2/libxslt 开发头 —— 装不上就会**安装失败**，而不是运行时变慢。
#     发布机与 CI 都是常见的 x86_64 Linux，wheel 是有的。
#   * 它改变 openpyxl 的解析器实现。openpyxl 两条路都受支持，但异常类型与
#     报错信息可能不同 —— 依赖具体报错文本的测试会需要核对。
lxml>=6.1.3

# FastAPI 的 File()/UploadFile() 靠它解析 multipart。缺了它不是启动报错，
# 而是**收到上传请求时才 500** —— 这类「跑起来才发现」的缺依赖最贵。
python-multipart>=0.0.32

# 只有 backend/Dockerfile 的 CMD 用它（systemd 路径不走 gunicorn）。

# 镜像里跑的是哪一版完全看构建那天 PyPI 的脸色。收进清单是为了能被 lock 定版。
gunicorn>=23.0.0
