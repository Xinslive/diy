# 插件扩展优化任务清单

日期：2026-10-18。当前交付阶段：**文件转凭证闭环（P0），以及它需要的账套配置能力**。后续 SDK 扩展列为独立待办，不计入本阶段已完成范围。

## 产品边界

管理员安装插件并向用户授予使用权；授权不绑定账套。用户在插件自己的页面选择目标账套，宿主逐次核验其账套角色。文件适配、转换规则、业务界面属于插件；宿主负责最终账务校验、事务、持久化和来源追溯。账套差异配置保存在插件自己的 book-scoped 表中。

每个批次只写一个账套；需要处理多本账时建立多个批次，分别预览、确认和提交。插件保持独立页面，不扩展宿主页面插槽。SDK 按能力逐步扩充，以覆盖公司内部多种业务需求。

### 同阶段完成的配置能力

- [x] `ctx.config.get/put` 和 `host.services.config.get/put` 只操作插件声明的 book-scoped 配置表。
- [x] 缺省配置为版本 0；写入采用 expected_version 比较并更新，返回版本和 SHA-256。
- [x] 解析时记录配置引用；确认和提交时重新核对版本与摘要。配置发生变化须重新解析并确认。
- [x] 配置 CAS 与导入提交使用同一账套事务锁，覆盖两个请求并发首次保存和配置变更。

### 交付与运行说明

SDK 版本升为 1.2.0，CWP 包格式保持 1；旧插件仍可使用原有 API。标准服务放在插件命名空间的保留路径 `/_host` 下，不能被插件路由覆盖。签名打包器忽略 Finder 的 `.DS_Store` 元数据，服务端仍核验实际包内的完整文件清单。1.2.0 增加应用级定时任务：管理员启用全局任务，宿主按当前有效授权逐用户扇出执行，并持久化租约、失败与幂等运行记录。

上线需执行主迁移到 `0031_subject_guard_year`，构建前端，并按既有插件流程安装、授权和重启。部署外部调度器每分钟调用 `/api/scheduler/tick` 后，插件导入清理和 OSS 备份可由宿主调度；不应再同时启用旧的 `cwq-oss-backup.timer`，避免重复备份。本次没有启用生产插件或部署服务。

具体验收结果和重跑命令统一记录在 [plugin-verification.md](plugin-verification.md) 的“SDK 1.2 定时调度追加验收”。

## P1：扩大 SDK 的业务覆盖面

这些项目尚未实现。它们决定平台能否持续承接更多种插件，应以新增的实际插件场景逐项验收。

| 优先序 | 待办 | 完成标准 |
|---|---|---|
| [ ] P1-1 | 期间、凭证、账簿、报表只读查询 | 明确 capability、账套权限、字段、筛选、稳定分页、数据量上限；插件无需调用宿主内部接口取数 |
| [x] P1-2 | 插件数据查询与批量操作 | **已交付受限过滤 + 分页 + 计数**：`ctx.data.read` 支持白名单字段过滤（eq/ne/lt/lte/gt/gte/in/like/is_null）、`limit`/`offset` 分页与排序，另加 `ctx.data.count`；账套范围仍由宿主强制附加，没有任意 SQL 入口。批量写入仍待做 |
| [ ] P1-3 | 通用附件与文件服务 | 源文件导入以外的附件上传、关联、下载、配额、留存和备份完整闭环 |
| [ ] P1-4 | 更完整的受控后台作业 | 较大文件异步解析、进度、取消、资源配额和更细粒度结果管理；本次 1.2.0 已交付周期任务、租约、失败记录和多用户扇出，但不等同于完整后台作业框架 |
| [ ] P1-5 | 事件与订阅 | 补充凭证创建、导入完成、期间关闭等事件；明确事务前后、失败影响、顺序、重试和幂等规则 |
| [x] P1-6 | 插件诊断和恢复管理页 | **已交付**：管理页「恢复 / 诊断」入口，可执行 reconcile、查看安装尝试记录、清理备份与隔离区、一键封禁签名密钥；后续再补 request_id 与健康指标视图 |
| [ ] P1-7 | 兼容与资源治理 | 形成 SDK 契约测试和升级兼容矩阵；配置迁移验证；可观测的插件容量、超时、耗时与失败指标 |

本轮（2026-10-20 审查修复）同时收紧了插件平台的边界：静态扫描由黑名单改为**导入白名单**，签名撤销在**加载期**同样生效，备份目录分域降级，备份与隔离区不再占用插件代码配额，插件前端资产改为凭短期票据访问。详见 [plugin-risk.md](plugin-risk.md) 与 [plugin-verification.md](plugin-verification.md)。

宿主当前提供上传/导入资源上限，尚未提供针对每个插件的 CPU、内存或线程强制配额。周期任务采用同步受信任 worker、有限租约和至少一次幂等语义；更完整的后台作业和更多事件仍需单独版本化。
