# 排错与错误码

先判断问题发生在“包校验”“插件加载”“用户授权”“账套权限”还是“业务请求”阶段。不要只看浏览器里的一个 500；管理页面、接口响应和服务日志里的插件 id、版本、摘要和 request id 应一起核对。

## 包无法安装

| 错误码 | 常见原因 | 处理方式 |
|---|---|---|
| `INVALID_MANIFEST` | 字段缺失、类型错误、未知字段或枚举值错误 | 对照 Manifest 参考，重新用工具构建 |
| `UNSAFE_PATH` | 包内有绝对路径、`..`、反斜杠、链接文件或重复路径 | 清理源目录后重新打包 |
| `INVALID_SIGNATURE` | 文件被修改，或清单与签名不一致 | 不要手工改 `.cwp`；重新构建并离线 verify |
| `UNTRUSTED_SIGNATURE` | `key_id` 不在运行环境的可信公钥列表中 | 使用已登记的发布密钥，或让管理员配置对应公钥 |
| `TABLE_METADATA_MISMATCH` | 迁移落地的表结构与 manifest 或已登记结构不一致 | 检查迁移、表名前缀和数据库状态 |
| `MIGRATION_SCOPE_VIOLATION` | 迁移触碰宿主表、其他插件表或不允许的外键 | 只创建插件自己的表，并按 scope 添加 `book_id` |
| `INVALID_TABLE_COLUMN` | 插件自有表声明了二进制列（`BYTEA`） | 把文件内容改成走导入批次通道（`ctx.imports`），表里只留结构化的值 |
| `DOWNGRADE_OR_REPLAY_REJECTED` | 版本降低或重复执行旧迁移 | 提高插件版本并新增 revision，不重放旧 revision |

构建工具输出的 `plugin_digest` 是定位包内容的最好线索。上传前在打包环境执行一次 `verify`，比上传后再猜错误原因快得多。

## 安装后显示未就绪

确认顺序：

1. 服务端是否已经启用插件平台；
2. 插件的 `desired` 状态是否为启用；
3. 安装或升级后是否按提示完整重启；
4. 所有 worker 是否加载同一个版本和摘要；
5. 服务日志中是否有迁移失败或 manifest 错误。

安装完成但没有重启时，插件不会热加载。升级后如果插件保持禁用，需要先启用，再按提示重启一次。

## 页面没有出现

先检查用户是否已被管理员授予插件使用权。新安装默认不授权任何人，管理员身份也不会自动绕过授权。授权变化后重新刷新页面；如果用户刚被撤权，旧页面会在下一次请求时失效。

前端入口还必须满足：

- `plugin.json` 的 `frontend_entry` 和 `menu` 同时存在；
- route 以 `/plugin/{id}` 开头；
- 前端模块是默认导出组件工厂；
- 样式和图片路径都指向包内已签名文件；
- 没有运行时 CDN、动态 import 外部依赖或 SFC 编译器。

## 接口返回 401、404、403 或 503

| 状态 | 含义 | 检查点 |
|---|---|---|
| `401` | 没有有效登录凭据 | 检查当前会话，不要在插件代码里硬编码 token |
| `404` | 用户没有插件使用权，或插件不可用 | 检查授权和插件运行状态；平台会用 404 隐藏未授权插件 |
| `403` | 插件已授权，但目标资源权限不足 | 检查 manifest capability、账套角色和 `book_id` |
| `503` | 插件 worker 尚未达到就绪条件 | 检查重启是否完成、所有 worker 是否使用同一包 |
| `500` | 插件 handler 有未处理异常 | 使用 request id 查日志，先修复插件异常 |

`canWrite`、页面上显示的菜单和本地缓存都不能替代后端权限判断。每个写入 handler 都应先调用相应的账套能力。

## 导入批次失败

文件转凭证流程请保留 `revision`，不要把旧页面的按钮请求重放到新预览上。常见错误如下：

- `IMPORT_REVISION_CONFLICT`：重新读取批次；
- `IMPORT_PLUGIN_CHANGED`：升级后用新版本重新解析；
- `IMPORT_CONFIGURATION_CHANGED`：重新读取账套配置并重新确认；
- `IMPORT_DUPLICATE` / `IMPORT_FILE_OVERLAP`：检查已有批次和文件内容摘要；
- `IMPORT_SUBMIT_FAILED`：按错误中的凭证序号修正，保存预览后再次确认；
- 500 + request id：先读取批次状态，再决定是否重试，避免盲目重复提交。

## 修改后仍然报旧错误

确认浏览器加载的是新摘要对应的前端资产，并完成一次登出/登录或刷新。服务端业务 API 和前端静态资产有不同的缓存语义；如果只替换了包文件而没有完成插件升级和重启，旧版本仍可能处于运行状态。

如果错误涉及迁移，不要直接编辑已经安装的表结构。增加新的 revision，先在隔离环境验证升级，再重新打包、升级和重启。
