# 插件开发总览

插件是运行在财务记账系统里的受信任扩展。一个插件可以同时提供后端接口、自己的前端页面、独立的数据表和账套级配置；宿主负责用户授权、账套权限、会计校验、文件留存和最终提交。

当前公开契约为 **SDK 1.1.0 / CWP 1**。如果你第一次开发插件，建议先阅读“快速开始”，完成一个最小插件，再回到本页和 API 参考查具体能力。

## 适合构建什么

插件适合把一项相对独立的业务流程接入系统，例如：

- 读取当前用户有权访问的账套，并提供自定义查询或业务页面；
- 在插件自己的表中保存账套配置、业务记录和处理结果；
- 接收文件，解析为凭证草稿，让用户检查、调整、确认后整批提交；
- 在期末结账等宿主事件发生后记录插件自己的审计事件。

插件负责业务规则和交互，宿主负责最终的权限判断、账务校验和事务边界。插件不需要复制宿主的登录逻辑，也不应该直接操作宿主数据库。

## 一个插件包含什么

| 部件 | 是否必需 | 用途 |
|---|---:|---|
| `plugin.json` | 是 | 声明插件身份、兼容的 SDK、权限、入口、菜单和数据表 |
| `backend/main.py` | 是 | 导出 `register(registrar, ctx)`，注册插件自己的 HTTP 接口和 hook |
| `frontend/index.js` | 否 | 导出接收 `host` 的组件工厂，提供插件页面 |
| `migrations/versions/*.py` | 按需 | 创建或升级插件自己的数据表 |
| `frontend/style.css`、图片等 | 按需 | 前端静态资源；必须随包签名 |

插件源目录用于开发，`.cwp` 是上传格式。签名工具会根据源目录生成文件清单和签名字段，源目录里的 `plugin.json` 不要手工填写 `files` 和 `signature`。

## 一次请求会经过哪些检查

1. 用户必须已登录，并且被管理员授予该插件的使用权。
2. 插件只能访问 manifest 中声明的 capability；未声明的 `ctx` 属性不会提供。
3. 读取或写入账套时，宿主再次检查用户对目标账套的角色和状态。
4. 凭证写入会复用宿主的科目、期间、金额精度和借贷平衡校验。
5. 文件导入的确认、提交和来源追溯由宿主保存，插件只负责解析规则和页面交互。

授权和账套权限是两层独立判断。页面上的 `canWrite` 只能用于调整按钮状态，不能代替后端校验。

## 开发前需要知道的边界

插件代码属于受信任代码：Python、迁移和同源前端 JavaScript 在宿主的运行环境中执行。签名、扫描和窄 SDK 用于控制发布来源与误装风险，不能把插件变成安全沙箱。只安装经过组织内部审阅的包，并把私钥放在受控的打包环境中。

前端使用预编译、自包含的 ESM。插件不能在运行时加载 CDN、远程模块或 SFC 编译器，也不能依赖未随包提供的 npm 包。后端不能取得宿主的 SQLAlchemy session、数据库连接或任意 SQL 接口。

## 从第一个插件到可发布包

1. 创建源目录和 `plugin.json`。
2. 写后端入口；需要页面时再加入前端入口。
3. 为插件表写线性迁移，并在 manifest 中声明表的 scope。
4. 用开发环境跑通接口、权限和错误处理。
5. 用 Ed25519 私钥构建并验证 `.cwp`。
6. 由管理员安装、授权用户并重启服务。
7. 检查插件状态、菜单、账套权限和失败路径。

页面目录按这条路径组织。先看“快速开始”，需要精确字段时看“Manifest、权限与运行时参考”，处理文件转凭证时看“数据导入 API”。

## 版本与兼容

`version` 使用 SemVer；`api_version` 声明插件接受的 SDK 范围，例如 `>=1.1.0 <2.0.0`。升级插件时，宿主会重新验证包、迁移和数据表结构；插件应把配置格式和数据变更写进迁移，避免在启动时偷偷改表。
