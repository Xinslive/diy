# 用友「总账」打印样式规格（复刻基准）

> 本文是**照着用友导出的样张量出来的**版式规格，作为我们总账打印改造的基准。
> 样张：`库存现金总账`（2024 年，泉州星悦荟商业管理有限公司），2026-10-22 采集。
>
> 量取方式：对样张做像素分析，定位表格的横竖线坐标，再据此还原列宽与行结构。
> 下文所有列宽都是**样张上的实测比例**，不是目测。

## 1. 这张纸长什么样

### 1.1 页眉（表格之上）

| 位置 | 内容 | 样式 |
| --- | --- | --- |
| 居中 | `库存现金总账` | 大号粗体，**标题下带一条横线**（样张实测有下划线） |
| 右上角 | `[正式账簿]` | 方括号包裹，右对齐 |
| 右上（第二行） | `页号:  1-1` | 右对齐，格式为「**当前页-该科目总页数**」 |
| 右上（第三行） | `本币名称: 人民币` | 右对齐 |

标题的构造是**科目名称 + 「总账」**：`库存现金` + `总账`。

> **页号口径（2026-10-22 需求方确认）**：`1-1` 的意思是「**这个科目的总账只有 1 页，这是第 1 页**」；
> 若该科目分两页，则两页的页号分别是 `1-2` 与 `2-2`。
>
> 即 **`页号 = <当前页>-<该科目总页数>`**，每个一级科目**各自从 1 开始编页**。
> 之前误读为「册号-页号」（把 1001 是首个一级科目当成了巧合），已更正。


### 1.2 科目行（表格紧上方，左对齐）

```
科目: 库存现金(1001)
```

`科目: ` 与科目名同字号；括号里的编码 `(1001)` **字号更小**，是附注而非主体。

### 1.3 页脚（表格之下，一行三段）

```
核算单位: 泉州星悦荟商业管理有限公司        制表: demo          打印日期: 2026.10.22
                                                                          [用友软件]
```

- 左：`核算单位: <公司名>`
- 中：`制表: <制表人>`
- 右：`打印日期: YYYY.MM.DD`（**点号分隔**，不是横杠）
- 右下第二行：`[用友软件]` —— 这是用友自己的产品水印，**我们不印**。

## 2. 表格结构（8 列 + 2 行表头）

### 2.1 列宽实测

样张表格总宽 781px，列边界在 x = 31 / 59 / 86 / 155 / 445 / 559 / 674 / 697 / 812。

| # | 列 | 宽度(px) | 占比 | 对齐 |
| --- | --- | --- | --- | --- |
| 1 | 月 | 28 | 3.6% | 居中 |
| 2 | 日 | 27 | 3.5% | 居中 |
| 3 | 凭证号数 | 69 | 8.8% | 居中 |
| 4 | 摘要 | 290 | 37.1% | 左 |
| 5 | 借方 | 114 | 14.6% | 右 |
| 6 | 贷方 | 115 | 14.7% | 右 |
| 7 | 方向 | 23 | 2.9% | 居中 |
| 8 | 余额 | 115 | 14.7% | 右 |

「方向」列窄到 23px，**表头里的「方向」是竖排的**（方在上、向在下）——这不是排版失误，是用友的固定写法。

### 2.2 两行表头

```
┌──────────────┬────────────┬───────────────────────┬────────┬────────┬────┬────────┐
│   2024年     │ 凭证号数   │        摘    要        │  借 方 │  贷 方 │方向│ 余  额 │
├───────┬──────┼────────────┼───────────────────────┼────────┼────────┼────┼────────┤
│  月   │  日  │            │                       │        │        │    │        │
└───────┴──────┴────────────┴───────────────────────┴────────┴────────┴────┴────────┘
```

- **第 1 行的「2024年」横跨「月 + 日」两列**（样张实测：该行在 x=59 处没有竖线）。
- 第 1 行之外，其余列的表头都**跨两行合并**（第 2 行在 x=86 之后没有竖线）。
- 第 1 行高 45px，第 2 行高 24px —— 第 1 行**明显更高**，因为要放「2024年」。

## 3. 行结构（一级科目一份，跨全年）

样张共 25 个数据行，行高一律 ~23px。**行型只有 5 种**，没有别的：

| 行型 | 月 | 日 | 凭证号数 | 摘要 | 借方 | 贷方 | 方向 | 余额 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 上年结转 | 空 | 空 | 空 | `上年结转` | 空 | 空 | 借 | 12,728.25 |
| 本月合计 | `01` | 空 | 空 | `本月合计` | 216,805.75 | 182,642.52 | 借 | 46,891.48 |
| 累计 | `01` | 空 | 空 | `累　　计` | 216,805.75 | 182,642.52 | 空 | 空 |
| 本年累计 | `12` | 空 | 空 | `本年累计` | 2,427,834.91 | 2,316,146.76 | 空 | 空 |
| 结转下年 | 空 | 空 | 空 | `结转下年` | 空 | 空 | 借 | 124,416.40 |

关键规则：

1. **「月」列在「本月合计」和「累计」两行都写同一个月份**，「日」列留空。
2. **「累计」行不写方向和余额** —— 方向/余额只出现在「本月合计」「上年结转」「结转下年」三行上。
3. **12 月的第二行叫「本年累计」，不叫「累计」**（年末那一期的累计行改用年口径）。
4. **「上年结转」行的余额 = 第一期「本月合计」行的期初**：
   `12,728.25 + 216,805.75 - 182,642.52 = 46,891.48` ✓
5. **「结转下年」行的余额 = 最后一期「本月合计」的余额**：
   12 月本月合计余额 124,416.40 ≈ 结转下年 124,416.40 ✓
6. 「累　　计」「摘　要」「借　方」等标签**中间插空格**，是全角字距的固定写法。
   - **「累　　计」中间是两个全角空格（U+3000）**，不是普通空格：全角空格占一个字宽，
     普通空格只占半字宽。用普通空格排出来，与样张并排看就是两个字的距离。
   - 这一条在代码里只有一个来源：`queries.general_ledger` 返回的 `summary`，
     屏幕、打印件、Excel 三处都直接用它，谁也不许另写一套标签。
7. 样张里**没有任何凭证明细行**，「凭证号数」「日」两列全程空白。

### 3.1 数字的算法（已用样张交叉验证）

```
本月合计行：
  借方 = 该月该科目发生额（借方）
  贷方 = 该月该科目发生额（贷方）
  余额 = 上月末余额 + 本月借方 - 本月贷方        ← 方向随之翻转

累计行：
  借方 = 本年累计借方（1 月起累加）
  贷方 = 本年累计贷方
```

用样张逐月验算（借方）：216,805.75 + 300,034.88 + 200,000 + 109,911.76 + 151,082.54
+ 200,000 + 100,000 + 500,000 + 200,000 + 300,000 + 150,000 = **2,427,834.93**，
与 12 月「本年累计」的 2,427,834.91 一致（末位差 0.02 为样张数字舍入）。

## 4. 我们现状与用友的差距

> **本节是改造前的记录**（2026-10-22 改造前）。差距已按第 5 节的确认口径全部关闭，
> 实现现状见第 6 节。留在这里是因为「当初差在哪、为什么这么改」比「现在长什么样」更耐用。

### 4.1 根本性差距：我们的「总账」不是用友的「总账」

| | 用友总账 | 我们的总账 |
| --- | --- | --- |
| 粒度 | **一个一级科目一份**，含其所有下级 | **一行一个科目**（与科目余额表同源） |
| 行 | 逐月「本月合计 / 累计」 | 每科目一行：期初 / 本期 / 本年 / 期末 |
| 看点 | 该科目**这一年的流水台账** | 各科目的**余额快照** |

我们的 `backend/app/ledger/queries.py::general_ledger` 直接委托给
`balance_sheet_of_accounts` —— 也就是说，**我们的总账本质上是科目余额表**。
用友的总账是另一张表：它按月展开。

### 4.2 已确认的缺陷：总账打印目前印出来是一张空表

- `DEFAULT_TEMPLATES["LEDGER"]` 的列 key 是
  `date / voucher_no / summary / debit / credit / direction / balance`
  （明细账的形状，是历史遗留）。
- 而 `printing/preview.py::general_rows` 产出的 key 是
  `code / name / level / opening_direction / opening / period_debit / period_credit /
  ytd_debit / ytd_credit / direction / closing`。
- 两者**只有 `direction` 一个键对得上**。`render_table_page` 按 `r.get(c["key"], "")`
  取值，取不到就是空串。

实测（`backend/.venv` 直接跑纯函数）：

```
general_rows 产出的键: ['__kind','closing','code','direction','level','name','opening',
                        'opening_direction','period_credit','period_debit','ytd_credit','ytd_debit']
LEDGER 模板的列 key: ['date','voucher_no','summary','debit','credit','direction','balance']
--- 实际渲染出来的表体 ---
|||借|
```

**打出来的总账只有「方向」一列有字，六个金额/文本列全空。** 仓库里没有任何用例
断言总账打印的表体内容（`test_print_scope_and_totals.py` 只断言状态码与跨账套
拒绝），所以这个缺陷一直没被测出来。

### 4.3 能复用的现成件

| 需要的东西 | 现成件 | 说明 |
| --- | --- | --- |
| 月度发生额 | `ledger/engine.py` 的 `Figures` | 逐期 `opening / period_dr / period_cr / dr_cum / cr_cum / closing` 都有 |
| 上卷到一级科目 | `engine.merge_by_code` | 已处理跨年按编码归并 |
| 方向 + 绝对值 | `ledger.engine.display_side` | 明细账与余额表已在用 |
| 「本月合计/累计」行型 | `queries.detail_ledger` 的 `MONTH_TOTAL` / `YTD_TOTAL` | 明细账已有这套行语义，可直接借用标签口径 |

**结论：数据层不缺能力，缺的是「按一级科目 + 按月」这张表的组装，以及与用友一致的行标签。**

### 4.4 缺字段

| 用友版式里的东西 | 我们有没有 |
| --- | --- |
| 本币名称 | **没有**。`Book` 只有 `company_name / name / start_year / start_month`，无币种列 |
| 「正式账簿」标记 | 没有这个概念 |
| 页号「册-页」 | 没有分册概念 |
| 核算单位 | 有（`Book.company_name`） |
| 制表人 | 有（当前用户） |
| 打印日期 | 可取当天 |

## 5. 已确认的口径（2026-10-22 需求方拍板）

四项设计分叉已由需求方逐项确认，实现按此落地：

| 问题 | 拍板结果 |
| --- | --- |
| 凭证明细行要不要印 | **只印汇总行**（与样张逐格一致），不展开凭证明细 |
| 打印范围与分册 | **账套全部一级科目，连续打成一册**（每个科目各自从第 1 页起编页） |
| 屏幕上的总账页 | **一起改成用友形态**：选一个一级科目 → 看该科目月度台账 |
| 页眉页脚复刻到什么程度 | **全套复刻**，本币名称固定写「人民币」（不加币种列） |

另外两条口径：

- **页号是「当前页-该科目总页数」**（`1-1` = 这个科目的总账只有一页，这是第一页；
  两页就是 `1-2`、`2-2`）。**不是**册号-页号 —— 之前误读为册号-页号，已更正。
- **不印 `[用友软件]`**（用友自己的产品水印），但保留右上角的 `[正式账簿]`。

## 6. 实现现状（2026-10-22）

| 层 | 落点 |
| --- | --- |
| 数据 | `backend/app/ledger/queries.py::general_ledger` —— 一个一级科目一份，逐月展开 |
| 版式 | `backend/app/printing/template.py::render_ledger_book_page` —— 两行表头 + 8 列 + 页眉页脚 |
| 导出 | `backend/app/printing/excel.py::general_ledger_excel` —— 一个一级科目一张工作表 |
| 打印端点 | `backend/app/api/printing.py` —— `/general-ledger.html`、`/general-ledger.xlsx` |
| 屏幕 | `frontend/src/views/ledger/GeneralLedger.vue` —— 八列，与打印件一致 |
| 用例 | `backend/tests/test_yonyou_general_ledger.py`（行型 / 数字算法 / 版式） |

**几个必须记住的实现约束**：

- **「累计」是区间累计**，不是每月重置 —— 为的是「期初 + 累计借 − 累计贷 = 期末」
  在任何区间都恒成立。区间恰好是整年时它就是用友的「本年累计」。
- **累计行不写方向与余额，期初行不写借贷方** —— 填了就是多出来的格子，
  与用友并排放两张纸一眼就能看出不是同一张。
- **打印件与导出件是同一张纸**：两边共用 `queries.general_ledger` 的同一份 `rows`。
- **整册只跑一次账簿聚合**：引擎的记忆化只在「已查到的上界 ≥ 本次上界」时盖得住，
  所以先把引擎热到区间最后一期再逐期取数；打一册时共用一个引擎实例。
- **屏幕上的科目按编码记，不按 id**：科目表每个年度各有一份，id 每年都变，
  跨年还认同一个科目只能认编码。

### 一处有意的例外

`backend/tests/test_excel_export.py` 有一条规则：「导出件的抬头里不出现单位名」
（`book.company_name`）。**总账页脚左段的「核算单位:」是例外** —— 那是用友正式
账簿的固定栏位（样张上就写着「核算单位: 泉州星悦荟商业管理有限公司」），
打印件里也有；导出件缺了它，两边就不是同一张纸了。
例外只放宽到**页脚那一格**：抬头里出现单位名照样红。
