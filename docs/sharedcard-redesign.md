### 银行资金守恒基线

按“同卡、同币种、同秒时间、同方向、同金额、同交易后余额”，加户名完整/脱敏兼容和跨文件唯一出现条件，合并来源投影。原始文件、行号、户名版本和归属证据均保留。

```
首笔交易前余额（反推）       1,536.10
+ 独立交易收入           1,715,662.05
- 独立交易支出           1,610,260.11
= 最后一笔交易后余额       106,938.04
```

直接把 12 份文件相加会额外计入收入 21,519.04、支出 105,000.00。这只是上传来源重叠，不代表生产凭证重复记账。

**余额衔接通过只说明已导入记录之间可接续；不证明银行提供了所有历史记录，也不代表账实核对已经完成。** 首笔前余额来自交易后余额与本笔收支反推，不冒称银行明确列示的期初余额。文件无交易日期的空档不直接判定为缺单，更不能把“没有流水”填成零。

### 账面资金守恒基线

对 100 个账套期间分别核验“权威期初＋原始分录借方－原始分录贷方＝权威期末”，全部相符；再校验各本账的上期期末与下期期初。逐笔余额从宿主期初接续，不从零开始，不随分页、候选排序、隐藏已核对项目重新计算。

```
2025-09 登记科目期初合计       199,094.98
+ 13 个期间借方发生额       4,107,755.37
- 13 个期间贷方发生额       3,845,613.35
+ 新启用账套的权威期初接入    -23,515.85
= 2026-09 登记科目期末合计     437,721.15
```

“待删除”在 2026-01 启用，期初为 -23,515.85，独立显示为**账套期初接入**，不是银行支出或会计发生额。旧账套“优境”仍在登记范围内，本次保留两本账及全部分录，不猜测应该删除哪一本，也不将相似分录自动去重。

**437,721.15 是全部登记账套 1001 科目的余额合计，不是本卡应有余额。** 登记科目可能包含现金、其他账户业务，并含未记账；必须先核实成员与科目范围、逐项建立本卡关联。没有本卡独立权威期初时，仅汇总“已核对到本卡的发生额”，不把已匹配分录从零滚成假的本卡余额。银行与账面区间也不同，不能直接相减并命名为账实差错。

## 2. 用户实际的工作主线

**进入卡 → 接入对账单 → 看银行与账面两条连续线 → 按异常核对 → 两边都能追溯核对关系。**

### 资金脉络（默认首页）

- 默认“双线并看”，另可展开完整银行流水或账面台账。银行按实际交易时间接续，账面按真实会计期间及凭证顺序接续，二者通过核对组连接。
- 一张卡一条按银行时间排列的台账；日期、收支、交易后余额、用途、当前归属和核对状态同屏。可切换资金顺序与最近在前。
- 月份是查看范围，不是隔断；跨月、跨文件选择一组交易不需要返回列表。
- 月末余额按银行自然月的最后一笔交易显示。文件跨到下月时，不把文件末笔余额误称为上月末余额。
- 一笔交易可有多个原始来源。点“2 份来源”查看各自文件、原始行号、户名版本与原归属，不重复计入收支。
- 银行日期、账面凭证日期、核对时选择的账期分别保存和显示；筛选账期不修改流水日期和凭证日期。

### 账面资金线（与银行线同级）

- 登记科目总览按月显示“期初、借方增加、贷方减少、期末、覆盖账套数”；选择一本账即可看连续的凭证收支及每笔后余额。合计是多个独立账套的加总，不伪装成银行当天余额。
- 每本账都保留“真实期初 → 逐笔收支 → 滚动余额 → 下期期初”。跨月、跨年与分页都不清零；即使一月内无分录，也显示其真实余额承接。
- 会计期间和凭证日期分别保留，以会计期间划定账面范围，不能仅凭凭证日期推算账期。跨年度用科目编码衔接年度科目实例，并用宿主权威锚点验证。
- 账套未启用、期间缺失、科目缺失、已记账/未记账、金额/发生额不一致分别表示。缺锚点时余额显示未知、校验不通过，不填零、不用差额补平。
- 从银行记录可追溯到已关联的分录及该分录在本账资金线中的位置；从账面分录可回看对应银行交易、多个原始文件及各自行号。已核对记录仍保留在两边资金线，不因移出候选而消失。
- “登记科目完整资金线”和“已证明属于本卡的账面发生额”是两层数据。没有独立本卡期初，不能声称后者已经构成完整本卡余额。

### 对账工作台

- 左侧银行交易，右侧账面分录。选择交易后直接列候选、账套、凭证日期、凭证号、现金科目、摘要和金额。
- 银行有、账上尚未关联；账上有、银行尚未关联；有候选但存在争用；已确认关系变更，分别显示。
- “未关联”不能直接写成“漏记/多记”：成员 1001 科目可能还包含现金等不属于这张卡的业务。
- 单笔等额只是候选提示。同一本账中有多笔候选，或同一分录被多笔银行交易竞争时，必须显式提示。
- 支持一对一、多对一、一对多和多对多的人工核对组；**同一核对组限定一个账套、一个收付方向和一种币种，收支分别守恒**。不做跨账套拆一笔银行金额，不把收入与支出净额抵平。
- 用途关键词和平台可用于筛选一组收款，但不自动据此写归属。汇总金额相等也不等于业务对应，不做任意子集凑数自动认账。
- 用户查看两边明细、日期及组内合计，差额为零后确认；没有可靠证据时可以保留待核对、记录疑点、导出询问。
- 旧人工归属不被批处理覆盖。若新选择账套与既有归属冲突，先显示冲突并处理归属；历史制证状态不能被普通核对或撤销动作解除。

### 原始资料

- 原对账单完整归档；显示实际交易日期范围、原始行数、复用来源数、增量交易数和解析诊断。
- 导入先解析并校验卡/币种，再做来源识别与余额接续预检。确认前展示“新增几笔、重叠几笔、从哪笔接到哪笔”。
- 同文件哈希重传幂等返回已有资料，不重新生成交易；不同文件覆盖同笔交易则增加来源关系。原件删除不级联删除仍有其他来源或核对关系的交易。
- 相同时间、金额但缺余额/流水号或身份有冲突的行只列为待确认，不自动丢弃。一个文件里出现两行相同记录也不按跨文件重复规则折叠。

### 成员账套与匹配范围

- 成员配置后置，保留现行权限范围。只读成员的账面分录仍参与候选展示，但不能承接写入。
- 卡级常用范围可选“银行当月”“银行上月”“上月及当月”“自选账面期间”；当前 12 份声明支持把“银行上月”作为这张卡的**建议**，不自动改写现有设置。
- 对个别交易/核对组可改账面期间范围。查找范围只是找证据，不能改变账期、创造业务归属或把所有跨月候选自动当成正确。
- 旧文件的匹配月份是历史证据；一笔重复流水在两份文件上的不同月份声明不再产生两笔独立业务或两条可重复占用的配对。

## 3. 原型已可体验的内容

原型用本次生产快照生成，不使用演示金额填补真实数据。支持双线并看、完整银行流水、账面逐本逐笔台账及跨期余额、跨年分页、启用期初接入提示、未记账标识、两侧核对关系互查、月份/方向/用途过滤、重叠来源追溯、卡级跨月范围选择、多选核对、分币合计与差额、同额争用提示、本页归属选择、在本页演示确认/撤销，以及重放 9 月文件的增量接入。

预览确认只修改页面内存，重新打开恢复快照；不会写回生产。真实银行上传、权限提交、数据库事务和原件下载仍属于后续插件实现范围，不能把原型按钮当成已发布接口。

## 4. 后端实施合同

在现有插件权限与宿主接口内扩展，不改宿主凭证、不生成凭证、不重新实现银行解析器。

| 对象 | 职责与关键约束 |
| --- | --- |
| import_batch | 原件/解析批次；哈希、卡、币种、解析版本、时间、诊断；保留原行及不可变来源 |
| bank_transaction | 卡级稳定交易身份；银行时间、收付方向、金额、交易后余额、银行流水号（有则优先）；不绑定单一文件或单一会计月 |
| transaction_source | 独立交易 ↔ 原文件行，多对多来源；原件重传幂等；不会重复增加资金 |
| ownership | 资金归属及人工/初筛依据；与核对状态分开；同一有效交易只能有一个有效目标账套 |
| reconciliation_group | 人工确认的同账套、同方向核对组；银行侧与账面侧总额分别相等，保存确认人、时间、选择范围、修订号 |
| bank_match_item | 核对组银行成员；同卡交易不得同时属于两个有效核对组 |
| entry_match_item | 核对组账面成员；稳定 entry_id，并保存 voucher_id、账套、科目、日期和金额快照；同一分录不得被重复占用 |
| review_note | 疑点、询问、暂未关联的处理记录；不伪造已核对状态 |

账面资金线是宿主账簿的只读投影，不再复制维护一套会计余额表。需要宿主在同一取数口返回稳定分录 ID、期间、状态、权威期初/期末与逐笔余额，以及 `book.data_version`。现有 `detail_ledger_read` 已有逐笔余额，但确认关联还需可靠分录 ID 和一致版本；不能从文字凭证号恢复一个猜测的关联。成员与登记科目范围也需单独的修订号。

账套级业务表继续沿用插件宿主的隔离、备份和权限约束。卡级身份不能靠“哪本账碰巧存了文件”决定；具体表的 scope 与跨账套事务，需在迁移前验证宿主数据 API 能力。**若宿主无法在一次事务中锁住整卡交易和分录占用，必须先补宿主原子能力；不能用多个 data.insert 调用冒充事务。**

建议接口：

```
GET  /cards/{id}/workspace                 # 资金链、月份、来源、范围与进度，带快照修订号
GET  /cards/{id}/transactions              # 连续分页，不按文件截断
GET  /cards/{id}/ledger-line               # 登记科目的跨期余额、覆盖范围、期初接入及断点
GET  /cards/{id}/ledger-line?book_id=...    # 权威期初、稳定分录 ID、逐笔余额和两侧核对引用
POST /cards/{id}/imports/preview           # 解析、幂等/重叠识别、余额接续预检
POST /cards/{id}/imports/commit            # 按预检修订号原子接入
GET  /cards/{id}/reconciliation/candidates # 两侧候选，保留所有争用证据
POST /cards/{id}/reconciliation/groups     # 原子占用两边成员并确认
POST /cards/{id}/reconciliation/{id}/revoke# 有审计的撤销，不删凭证
GET  /cards/{id}/ledger-unlinked           # 账上待核对清单，尊重选择范围与科目范围
GET  /cards/{id}/exports                   # 筛选后的连续流水/待核对/账面逐笔 Excel
```

分页使用银行时间与稳定交易 id 游标；余额在整卡排序后计算与校验，不能用当前页或筛选子集重新滚余额。核对确认重查真实分录及权限，采用修订号/行锁和唯一有效占用约束防并发；凭证被改期、改金额、删除或撤销时，原核对组转为“关联变更待复核”，保留原证据。

导出账面明细账仍遵守原有逐笔七列口径；核对关系和文件来源可以另表导出，不把期初/合计行混进原账面明细账。

## 5. 迁移与上线验收

1. 保存当前包、快照、逐文件行数、资金控制总额和逐条人工归属基线；在隔离副本预演。
2. 原 859 行和原件完整保留，建立 823 笔候选身份及 859 条来源关系；只有证据充足、余额链校验通过的重叠才复用。
3. 旧 152 条归属保留来源证据，投影为 138 笔单一归属及 7 笔归属冲突；冲突单列，不选“最新一条”覆盖。旧初筛不升级为已确认核对。
4. 137 条初筛没有稳定分录引用，不能按“凭证号＋日期差”反查一个看起来最近的分录并冒充历史人工确认。需要重新建立分录关联。
5. 完成增量导入重放、重复上传、跨年/跨月、脱敏差异、同秒多笔、同文件重复、缺余额、来源归属冲突、多对一/一对多、分录争用、撤销、凭证变更、权限不足和并发占用验证。
6. 对照 12 个银行自然月、全部 823 笔资金、152 条原归属，以及 13 个账面期间、404 笔分录、100 个余额锚点与启用期初 -23,515.85；逐本逐期的收支守恒、跨月跨年和分页承接必须相符。不得用登记科目总余额代替卡余额。
7. 在独立浏览器和隔离验证库完成真实上传、确认、撤销和页面状态恢复；生产发布及数据迁移另按正式流程执行。

本次离线工具验证资金身份、两侧余额链、来源与候选，不替代未来持久化/并发/权限的后端测试，也不宣称生产插件已具备以上新接口。
